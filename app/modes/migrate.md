# 迁移一个现有的 bot

开发者已经有一个 bot,想搬到 Cortico 上。产出先是一份预案,确认后才是包。

1. **要目录。** 请开发者给旧 bot 的目录。它在本工作区之外,读它之前要开发者说一句同意;只读,
   不改。
2. **读清四件事**,写进 `state/design/migrate-<名>.md`。读之前先按阅读地图把 bot 与 World 两节读完,
   读旧代码时才知道在找什么。
   - 上下文的组织方式:系统提示怎么拼、历史怎么进、什么时候截断 → Persona 的前缀段与交接;
   - 内部语义信息怎么持久化:人格、记忆、关系、笔记存在哪、什么形状 → Memory;
   - 外部 IO:接了哪些平台、设备、游戏,各自进什么、出什么 → 一个或多个 World;
   - 会话生命周期:什么时候醒、什么时候结束一轮、多个会话怎么分 → session 声明与触发档位。
3. **出预案。** 一份 Markdown 给开发者过:
   - 映射表:旧 bot 的每一块对应 Cortico 的哪一层;
   - 包清单:一个 bot、一种 Memory、一个或多个 World,各自做什么,先做哪个;
   - 历史数据:旧的记忆、对话记录、状态文件搬不搬、搬到哪、怎么转;
   - 为旧模型的局限写的机制:迁移的第一目标是还原,所以照搬,按 PHILOSOPHY.md 的第一条准则标成
     fallback;要不要去掉是迁移完成之后的事。
   预案由开发者逐项确认或改掉;确认前不动手写包。
4. **逐包做。** 按 `world.md`、`bot.md` 的流程一个一个来;World 先于 bot,bot 的 `declares` 才有
   东西可写。
5. **完成。** 预案里的每个包各自过三级。不另列行为清单:开发者发现不对会跟进。
